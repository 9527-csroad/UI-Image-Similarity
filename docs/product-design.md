# UI 图像相似度对比工具 — 产品设计方案

## 1. 产品定位

- **一句话描述**：一款面向桌面端 Web 的 UI 截图相似度对比工具，用户上传两张界面截图即可获得多维度相似度评分与可视化差异分析。
- **目标用户**：
  - 前端/全栈工程师：做视觉回归对比，确认 UI 变更是否符合预期。
  - UI/UX 设计师：对比设计稿与实现效果、或对比两版设计方案。
  - 测试工程师：快速判定两次截图之间是否存在肉眼难以察觉的差异。
  - 产品/运营人员：对比 A/B 方案或活动页面上线前后的效果差异。
- **解决的核心问题**：人眼对比两张 UI 截图效率低、容易遗漏细微差异（1-2px 偏移、颜色微调）；需要一种工具能快速给出量化评分并高亮差异区域，辅助决策。

---

## 2. 功能范围（基于研发调研）

### 2.1 核心功能（P0）

#### 双图上传（拖拽 + 点击）
- 支持拖拽上传和点击选择文件两种方式。
- 支持格式：PNG、JPG/JPEG、WebP、BMP（调研报告涉及的格式，均为常见截图格式）。
- 单张文件大小上限：10 MB。
- 同时校验：两张图上传完毕后才激活"开始对比"按钮。

#### 相似度计算与结果展示
- 基于调研推荐方案 **SSIM + dHash + HSV 直方图** 加权融合，返回三个子分数和一个综合分。
- 综合分 = 0.50 * SSIM + 0.25 * dHash + 0.25 * 直方图（Correlation）。
- 结果以百分比形式展示，保留小数点后 1 位（如 `87.3%`）。
- 根据综合分给出定性判定标签：

| 综合分区间 | 标签 | 颜色 |
|-----------|------|------|
| >= 90% | 高度相似 | 绿色 |
| 70% - 89% | 中度相似 | 橙色 |
| < 70% | 差异较大 | 红色 |

#### 差异可视化
- **差异热力图模式**：SSIM 计算时生成逐像素 diff 矩阵，渲染为热力图覆盖在原图上（差异区域以暖色高亮，无差异区域以原图/半透明显示）。
- **Slider 对比模式**：两张图上下叠放，中间有一条可拖拽的垂直分割线，向左/右拖动分别展示图 A/图 B 的区域。

### 2.2 辅助功能（P1）

#### 图像预览与对比模式切换
- 页面上始终展示已上传的两张图的缩略预览。
- 对比模式可在以下三种之间切换（Tab 或 Radio 按钮）：
  1. **并排对比**：左右各一张原图，等高缩放，底部对齐。
  2. **叠加 Slider**：两张图叠加，拖拽分割线切换可见区域。
  3. **差异热力图**：在图 A 上叠加 SSIM 逐像素差异热力层。

#### 相似度分数详情（多维度拆解）
- 展示卡片包含：
  - **综合分**（大号字体，主视觉）
  - **结构分（SSIM）**：反映像素级结构相似度。说明文字："衡量图像亮度、对比度、结构的综合相似度，对 1-2px 偏移极度敏感。"
  - **布局分（dHash）**：反映整体布局相似度。说明文字："基于图像梯度结构生成指纹，对亮度变化和轻微缩放鲁棒。"
  - **颜色分（HSV 直方图）**：反映颜色分布相似度。说明文字："基于 HSV 颜色空间直方图对比，换肤场景下可能偏低。"
- 每个子分数以进度条 + 数值形式展示。
- 附带一段简短的**智能解读**，根据分数组合自动生成，例如：
  - "结构分和布局分均较高，但颜色分偏低 — 可能为换肤/主题切换导致。"
  - "结构分较低但布局分较高 — 元素位置未变，但内容/文字有较大修改。"

#### 历史记录（最近 N 次对比）
- 本地存储（LocalStorage / IndexedDB）最近 10 次对比记录。
- 每条记录包含：缩略图 A/B、综合分、对比时间。
- 点击可回看该次对比结果（重新渲染，无需重新计算）。
- 提供"清除全部"操作。

### 2.3 未来规划（P2）

#### 批量对比
- 上传 N 张图片，选择一张作为基准，批量对比其余 N-1 张。
- 输出矩阵表格（N-1 行，含综合分和各子分数）。
- 支持按分数排序、筛选。

#### API 接入
- 提供 RESTful API，接收 Base64 编码的图像数据，返回 JSON 格式的相似度分数。
- 支持接入 CI/CD 流程做自动化视觉回归检查。

#### 导出报告
- 导出 PDF 或 PNG 格式的对比报告，包含：两张缩略图、各维度分数、差异热力图、对比时间。
- 适用于归档和团队协作场景。

## 3. 用户故事

### US-1：上传两张截图并对比
**作为** 一名前端工程师，**我希望** 能上传两张 UI 截图并获取相似度评分，**以便于** 快速确认 UI 变更是否符合预期。

**验收标准**：
- Given 用户在页面上，When 用户通过拖拽或点击上传了第一张图，Then 页面显示该图预览，并提示"请上传第二张图"。
- When 用户上传了第二张图，Then "开始对比"按钮变为可用状态。
- When 用户点击"开始对比"，Then 页面进入加载状态，计算完成后展示综合分数、三个子分数和差异可视化。
- When 计算完成，Then 整个流程从上传到结果展示不超过 5 秒（以 1080p 图像为基准）。

### US-2：切换对比模式查看差异
**作为** 一名 UI 设计师，**我希望** 能在并排、Slider、热力图三种模式间切换，**以便于** 从不同角度观察两张图的差异。

**验收标准**：
- Given 用户已查看对比结果，When 用户切换对比模式 Tab，Then 视图在 200ms 内完成切换，无闪烁。
- When 在 Slider 模式下，Then 用户可拖拽垂直分割线，分割线拖动过程流畅（60fps）。
- When 在热力图模式下，Then 差异区域以红色/橙色高亮显示，用户可通过滑块调节热力图透明度（0%-100%）。

### US-3：查看多维度分数详情
**作为** 一名测试工程师，**我希望** 能看到结构分、布局分、颜色分的独立数值，**以便于** 判断差异的具体类型。

**验收标准**：
- Given 对比结果已展示，Then 页面显示综合分 + 三个子分数，每个分数以百分比 + 进度条形式呈现。
- When 用户将鼠标悬停在某个子分数上，Then 显示该维度的说明 tooltip。
- When 分数组合满足特定模式时，Then 页面显示智能解读文字（至少覆盖换肤、布局未变内容变、高度相似三种模式）。

### US-4：查看历史对比记录
**作为** 一名产品人员，**我希望** 能查看最近 10 次的对比记录，**以便于** 回顾之前的对比结果。

**验收标准**：
- Given 用户完成了至少一次对比，When 用户点击"历史记录"区域，Then 展示最近 N 条记录，按时间倒序排列。
- When 用户点击某条记录，Then 页面恢复该次对比的完整视图（缩略图 + 分数 + 差异可视化）。
- Given 记录数超过 10 条，When 新完成一次对比，Then 最旧的一条自动被移除。
- When 用户点击"清除全部"并确认，Then 所有本地存储的记录被删除。

### US-5：处理异常上传
**作为** 一名用户，**我希望** 在上传失败或格式不支持时得到明确提示，**以便于** 快速修正操作。

**验收标准**：
- When 用户尝试上传非图片文件（如 .txt、.pdf），Then 拒绝上传并显示 toast："不支持的文件格式，请上传 PNG、JPG、WebP 或 BMP 图片。"
- When 用户上传的图片超过 10 MB，Then 拒绝上传并显示 toast："文件大小超过 10 MB 限制，请压缩后重试。"
- When 用户上传的两张图尺寸差异过大（长或宽相差超过 5 倍），Then 显示 warning："两张图尺寸差异较大，可能影响对比精度。" 对比仍继续执行，后端自动缩放。
- When 用户中途取消上传，Then 已上传的第一张图预览保留，状态恢复为"等待第二张图"。

### US-6：导出对比结果
**作为** 一名测试工程师，**我希望** 能将对比结果导出为图片，**以便于** 在缺陷管理系统中附加截图凭证。

**验收标准**（P1 实现为 PNG 导出，PDF 为 P2）：
- Given 用户已查看对比结果，When 用户点击"导出为 PNG"按钮，Then 浏览器下载一张 PNG 文件，包含两张缩略图、分数卡片、差异热力图。
- When 导出文件名格式为 `image-compare-YYYYMMDD-HHmmss.png`。

### US-7：对比两张几乎完全相同的图
**作为** 一名工程师，**我希望** 在两张图几乎相同时仍能获得有意义的反馈，**以便于** 确认是否存在肉眼不可见的 1px 级差异。

**验收标准**：
- When 两张图完全相同，Then 综合分 = 100.0%，标签显示"完全相同"（蓝色），热力图全黑（无差异）。
- When 两张图仅有 1-2px 差异，Then SSIM 分应反映该微小差异（根据调研 SSIM 对 1px 偏移极度敏感），综合分可能降至 95% 以下，热力图精确高亮差异像素。

## 4. 交互流程

### 4.1 完整操作流程

```
[打开页面]
    |
    v
[主页面展示]
  - 顶部：产品标题 + 简短描述
  - 中央：两个上传区域（左 = 图 A，右 = 图 B）
  - 底部：历史记录区域（折叠态，显示"最近 X 次对比"）
    |
    v
[用户上传图 A]（拖拽或点击选择文件）
  - 校验格式和大小
  - 校验通过 -> 上传区域变为图 A 预览（带"更换"按钮）
  - 校验失败 -> toast 提示错误，上传区域不变
    |
    v
[用户上传图 B]
  - 同图 A 流程
  - 上传成功后，"开始对比"按钮从 disabled 变为 enabled（主色高亮）
    |
    v
[用户点击"开始对比"]
  - 按钮变为 loading 态（旋转 spinner + "计算中..."文字）
  - 上传区域上方出现进度提示（"正在分析图像结构..." -> "正在计算布局相似度..." -> "正在生成差异热力图..."）
  - 预计耗时：2-5 秒（1080p 图像）
    |
    v
[结果展示]
  - 页面分为上下两部分：
    上部：综合分大卡片 + 三个子分数进度条 + 智能解读文字
    下部：对比视图（默认并排模式），含模式切换 Tab（并排 | Slider | 热力图）
  - 右侧浮出操作栏：导出 PNG、重新对比（清空重置）、保存到历史
    |
    v
[用户切换对比模式]
  - 点击 Tab，视图切换，无页面刷新
  - Slider 模式：用户可拖拽分割线
  - 热力图模式：用户可调节透明度滑块
    |
    v
[用户操作后续]
  - 可点击"重新对比" -> 清空所有状态，回到初始上传页
  - 可点击"导出" -> 下载 PNG
  - 可点击"历史记录" -> 展开侧栏/底部面板
```

### 4.2 异常流程

| 异常场景 | 触发条件 | 系统行为 |
|---------|---------|---------|
| 文件格式不支持 | 上传非图片文件 | 拒绝上传，toast 提示"不支持的文件格式"，文件被丢弃 |
| 文件过大 | 图片 > 10 MB | 拒绝上传，toast 提示"文件超过 10 MB 限制" |
| 两张图尺寸差异过大 | 长或宽相差 > 5 倍 | 显示 warning banner（可关闭），后端自动 resize 到较大图的尺寸，对比继续进行 |
| 两张图宽高比不同 | 宽高比不一致 | 显示 info 提示"两张图比例不同，可能影响对比结果"，对比继续进行 |
| 两张图完全相同 | 文件内容完全一致 | 综合分 = 100%，显示"完全相同"标签，热力图全黑 |
| 两张图完全不同 | 综合分 < 20% | 显示"差异较大"标签，热力图全红，智能解读提示"两张图内容完全不同，请确认是否上传了正确的对比图" |
| 网络中断 | 计算过程中断网 | 显示 error banner："计算中断，请检查网络连接后重试"，提供"重试"按钮 |
| 后端超时 | 计算超过 10 秒未完成 | 显示 error banner："计算超时，请尝试使用更小尺寸的图片"，提供"重试"按钮 |
| 仅上传一张图 | 用户点击"开始对比"时只有一张图 | 按钮保持 disabled，不会出现此情况 |
| 历史记录已满 | 超过 10 条记录 | 新记录入队时自动移除最旧记录，静默处理，不弹提示 |
| 本地存储不可用 | 浏览器禁用 LocalStorage | 历史记录功能降级为不可用，显示提示"当前浏览器不支持本地存储，历史记录不可用"，不影响核心对比功能 |

## 6. 关键交互细节

### 6.1 上传交互规范

**上传区域状态**：

| 状态 | 视觉表现 | 行为 |
|------|---------|------|
| 空闲 | 虚线边框（2px dashed，#D1D5DB），浅灰背景（#F9FAFB），中央有上传图标 + "拖拽或点击上传"文字 | 支持拖拽进入高亮；支持点击触发文件选择器 |
| 拖拽悬停 | 边框变为主色（#3B82F6），背景变为主色浅色（#EFF6FF），文字变为"松开以上传" | 检测 `dragover` 事件，仅对图片 MIME type 高亮 |
| 上传成功 | 虚线边框消失，变为实线圆角卡片（4px rounded），展示图片缩略（固定高度 200px，object-fit: contain），右上角有 "更换" 图标按钮 | 缩略图下方显示文件名和尺寸信息（如 `screenshot.png · 1920x1080 · 2.3 MB`） |
| 上传失败 | 边框变为红色（#EF4444），背景变浅红（#FEF2F2），显示错误图标和错误文字 | 3 秒后自动恢复空闲态；或用户手动关闭 |

**文件选择器**：
- `accept` 属性：`image/png, image/jpeg, image/webp, image/bmp`
- `multiple`：false

### 6.2 结果展示规范

**综合分展示**：
- 使用环形进度条（SVG circle），直径 120px，线宽 8px。
- 进度条颜色根据区间：>= 90% 绿色（#10B981），70-89% 橙色（#F59E0B），< 70% 红色（#EF4444）。
- 环形中央显示百分比数值（36px 粗体）。
- 环形下方显示定性标签（14px，带彩色圆点前缀）。

**子分数展示**：
- 每个子分数一行，包含：
  - 左侧：维度名称 + 缩写（如 "结构分 SSIM"，14px，#374151）
  - 中间：进度条（宽度 200px，高度 8px，圆角 4px），进度条颜色同综合分逻辑但使用单一色
  - 右侧：百分比数值（14px 等宽字体，如 `85.2%`）
- 三个进度条垂直排列，间距 12px。

**智能解读**：
- 位于子分数下方，用浅灰背景卡片包裹（#F3F4F6，圆角 8px，padding 12px 16px）。
- 左侧有一个灯泡/info 图标。
- 文字 14px，#4B5563。
- 规则引擎（基于分数组合）：

| 条件 | 解读文案 |
|------|---------|
| SSIM >= 90 且 dHash >= 90 且 直方图 >= 90 | "两张图高度一致，未发现明显差异。" |
| SSIM >= 90 且 dHash >= 90 且 直方图 < 70 | "结构和布局一致，但颜色分布差异明显 — 可能为换肤/主题切换。" |
| SSIM < 70 且 dHash >= 80 | "整体布局相似，但内容或文字有较大变化。" |
| SSIM >= 80 且 dHash < 70 | "局部结构相似，但整体布局发生了变化 — 可能为响应式重排或组件重组。" |
| 综合分 < 30% | "两张图内容差异较大，请确认是否上传了正确的对比图片。" |
| 其他 | "两张图存在中等程度差异，建议通过下方对比视图查看具体差异区域。" |

### 6.3 对比模式切换

**Tab 切换**：
- 三个 Tab 水平排列，选中态有底部 2px 主色下划线，未选中态为灰色文字。
- 切换时当前视图淡出（opacity 200ms），新视图淡入。

**并排模式**：
- 两张图左右排列，中间有 2px 分隔线。
- 等高缩放，最大高度为容器高度的 80%。
- 每张图下方标注文件名。

**Slider 模式**：
- 两张图完全叠加，图 A 在底层，图 B 在上层。
- 中间有一条垂直分割线（3px 宽，白色，带阴影），中央有一个圆形拖拽手柄（24px 直径，白色背景 + 左右箭头图标）。
- 拖拽范围覆盖整个视图宽度。
- 分割线左侧显示图 A，右侧显示图 B（通过 CSS clip-path 或 overflow: hidden + width 控制）。
- 拖拽过程要求 60fps，无卡顿。

**热力图模式**：
- 以图 A 为底图，叠加 SSIM diff 矩阵渲染的热力图层。
- 热力图配色方案：差异值 0 = 完全透明，差异值 1 = 半透明红色（rgba(239, 68, 68, 0.6)），中间值使用红-橙-黄渐变。
- 右下角有一个透明度滑块（0-100%），默认为 60%，用户可以调节热力层透明度。
- 热力图模式下单图展示，无需两张图并排。

### 6.4 加载状态和错误处理

**加载状态（计算中）**：
- "开始对比"按钮变为 loading 态：按钮宽度不变，内部文字替换为 spinner + "计算中..."。
- 上传区域变为半透明（opacity: 0.5），不可交互。
- 在上传区域和按钮之间显示阶段提示文字，依次切换：
  1. "正在分析图像结构..." (SSIM 计算)
  2. "正在计算布局指纹..." (dHash 计算)
  3. "正在对比颜色分布..." (直方图计算)
  4. "正在生成差异热力图..." (diff 渲染)
- 每个阶段停留约 0.5-1.5 秒（可根据实际计算耗时动态调整）。

**错误处理**：
- 错误统一使用 Banner 样式：红色背景（#FEF2F2），红色边框（#FECACA），左侧红色感叹号图标，错误文字，右侧关闭按钮。
- Banner 出现在页面上方（Header 下方，Main Content 上方），不遮挡上传区域。
- 错误 Banner 包含具体错误信息和可操作建议（如"请检查文件格式"、"请尝试更小尺寸的图片"）。
- 对于可重试的错误（网络超时、计算超时），Banner 右侧额外显示"重试"按钮。
- 错误 Banner 不自动消失，需要用户手动关闭。

## 7. 技术能力对产品的约束

### 7.1 完全可以实现（基于调研确认）

| 能力 | 依据 |
|------|------|
| SSIM 计算 + 逐像素 diff 热力图 | `scikit-image` 的 `structural_similarity(full=True)` 直接返回 diff 矩阵，1080p 图像仅需 10-30ms。 |
| dHash 布局相似度 | `imagehash` 库提供 dHash，64-bit 运算，毫秒级完成。 |
| HSV 直方图颜色相似度 | OpenCV `calcHist` + `compareHist`，5-10ms。 |
| 三维度分数加权融合 | 简单数学运算，无技术障碍。 |
| Web 端像素级对比 | `pixelmatch`（2KB）和 `Resemble.js` 可在浏览器端完成像素对比和差异图生成。 |
| SSIM JS 实现 | `ssim.js` 纯 JS 实现，可部署在前端或后端。 |
| 图像预览和 Slider 交互 | 纯前端 Canvas/CSS 实现，无算法依赖。 |

### 7.2 有难度 / 需要额外工作

| 能力 | 难点说明 | 产品侧应对 |
|------|---------|-----------|
| SSIM 对 1px 偏移极度敏感 | 调研明确指出这是 UI 场景的"致命问题"，同一页面截图若存在 1-2px 位移，SSIM 会骤降。 | 产品上需要向用户明确说明这一点：当用户看到 SSIM 分数偏低时，智能解读中应提示"可能是像素级偏移导致，建议先对齐图片"。未来可考虑加入图像自动对齐预处理（使用 ORB 特征点）。 |
| 直方图在换肤场景下误判 | 换肤时颜色方案完全变化，直方图会判定为"完全不同"，但结构一致。 | 产品上通过多维度分数独立展示来解决 — 用户可以清楚看到结构分高但颜色分低，智能解读也会提示换肤可能性。 |
| dHash 精度有限 | dHash 将图像压缩到 9x8 再做差异，丢失大量 UI 细节。 | 产品中 dHash 仅作为辅助指标（权重 25%），主指标仍然是 SSIM。 |
| 大尺寸图像处理性能 | 超过 1080p 的图像（如 4K 截图）SSIM 计算时间会增加 4 倍。 | 产品设置 10 MB 文件大小上限 + 后端自动降采样到最大 1920px 宽度。前端对超大图在上传时给予提示。 |

### 7.3 暂不实现 / 未来考虑

| 能力 | 原因 | 未来触发条件 |
|------|------|-------------|
| CLIP 语义相似度 | 需要 GPU 或强 CPU，模型加载 151M+，推理 100-300ms（CPU），部署复杂度高。 | 当用户反馈"两张图看起来很像但分数很低"的场景增多时，考虑引入 CLIP 作为第四维度。 |
| 特征点匹配（SIFT/ORB） | UI 图像特征点极少（大面积纯色区域），调研评分仅 3/10。 | 仅在需要处理"截图被裁剪/缩放/旋转后对比"的场景时，作为预处理对齐步骤引入 ORB。 |
| Siamese Network | 需要标注数据集、GPU 训练、部署复杂，调研认为 MVP 阶段投入产出比不高。 | 当积累足够多的 UI 图像对比数据且现有算法满意度不足时考虑。 |
| LayoutParser 布局分析 | 需要 OCR + 目标检测模型，部署复杂，单次检测 500ms+。 | 当用户需要"元素级别差异报告"（如"按钮 A 向右偏移了 5px"）时考虑。 |
| 批量对比、API、导出报告 | 属于 P2 功能，不在 MVP 范围。 | 核心功能稳定后按优先级迭代。 |

### 7.4 技术架构对产品形态的影响

根据调研报告推荐的技术架构：

```
前端 (Web)                    后端 (Python FastAPI)
  |                                 |
  |-- 上传两张图 (FormData) -------->|
  |                                 |-- 图像预处理 (resize/crop)
  |                                 |-- SSIM (scikit-image)
  |                                 |-- dHash (imagehash)
  |                                 |-- 直方图 (OpenCV)
  |                                 |-- 分数融合
  |<-- JSON {ssim, dhash, hist,    |
  |          combined, diff_data} --|
  |                                 |
  |-- Canvas 渲染 diff 热力图       |
```

- **计算放在后端**：SSIM + dHash + 直方图计算均放在后端 Python 服务中（利用 scikit-image、imagehash、OpenCV 的成熟实现），前端仅负责上传、接收结果和可视化渲染。
- **前端可备选纯客户端方案**：`pixelmatch` + `ssim.js` 可在前端完成基础对比，作为后端不可用时的降级方案。
- **diff 数据传递**：后端返回 SSIM diff 矩阵（可压缩为 base64 PNG 或降采样后的 JSON 数组），前端 Canvas 渲染为热力图。对于 1080p 图像，diff 矩阵作为 PNG 传输约 50-200KB，可接受。
